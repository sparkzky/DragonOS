### 拆分策略上的偏离与理由

1. **§3.6-1（futex）不开 PR**：核对 `origin/master` 的 `futex_wait()` 已是 Linux `futex_wait_setup` 语义（`read_user_u32_nofault` + 缺页放锁重试），重复开 PR 会与既有实现冲突。
2. **§3.6-3 与 §3.6-8 合并为一个 PR**：track_caller 的唯一用途是定位 shootdown 发起者，二者共享同一份诊断设施，分开反而产生"日志无消费者"的半个 PR。
3. **§3.6-5 收窄**：`master` 并不含任何 R16 探针，因此"删除锁内 console 探针"在 master 上已天然满足；本 PR 只落**净增量**（rq 哨兵 + tmict 采样基线修正 + 编译期打印开关 + `set_next_task` 重复武装删除）。`debug/task_dump.rs` 的 stall watchdog、`time/deadline.rs` 的 dlprobe 需要尚未合入的 critical 输出通道（`printk.rs`），故未纳入（见 §3/§4）。
4. **§3.6-7 实现方式调整**：参考实现用 `wait_event_uninterruptible_timeout(.., 1s)`；master 的 `submission_wait` 已是 `ResourceWaitQueue`（#2488/#2489 重构），**无超时等待 API**。为避免侵入 wait 队列子系统，改为等价的"1s 周期自检 kthread"（语义相同，且提交方永久阻塞时仍能发声）。
