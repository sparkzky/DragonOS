## 0. 通用规则

1. 每个拆分项：`git switch -c <branch> origin/master`（或 `git switch --detach origin/master` 建新分支）。
2. 从源 worktree 取补丁：`git -C ~/DragonOS-ocmanager show <sha>` 或 `format-patch -1 <sha> --stdout | git am`；
   冲突时按 master 上下文手工移植，**只保留该修复的语义**，不要带入本分支的脚手架/诊断。
3. 每分支必须：`make kernel` 输出 `Kernel Build Done`（BUILD=0）、`make -C kernel fmt` 通过。
   仓库根 `make fmt` 在 `user/apps/*` 存在既有缺 target 问题，以 `make -C kernel fmt` 为准。
4. 通过后：`git push sparkzky <branch>`，`gh pr create --repo DragonOS-Community/DragonOS --base master --head sparkzky:<branch>`。
5. 若该修复在 `origin/master` 已存在（按内容核对，勿轻信提交信息），跳过并在报告中说明。
6. 若某项与 master 差异过大、无法在“只保留该修复”的前提下编译通过，记录原因并跳过，不要提交半成品。
7. PR 描述必须包含：根因、证据、验证方式（`make kernel` / 场景复现）、影响的文件。
